Two practical findings on the way:

- A `t` level's kernel set is ~16x an `n` set's (1.35M bodies against 85k;
  exact floor states x timers), ~13 GB resident; the default keeps every
  prebuilt set, so four `t` sets alone filled the cap. `CELESTE_KERNEL_SETS=1`
  (rebuild per level, ~75 s) is required for `t` ladders in this room. And the
  prebuild of all finer levels at once (16 walk threads each) ran out of memory
  before any frame: `CELESTE_KERNEL_SETS` caps that too.
- `rewrite witness --level K` takes K as `Bits(K)` with everything else exact;
  it cannot follow a `CELESTE_LADDER` level (n, t, h), so there is no cheap way
  yet to see WHICH over-approximation the f164 coarse wins use. That is the
  next tool to build: a witness/`spurious` that takes the ladder spec.
