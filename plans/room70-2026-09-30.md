# Room (7,0) "800 m" (2026-09-30, Philippe hands-off)

Branch `step5-split`. Split frame (`CELESTE_SPLIT_FRAME=1`, two steps a frame),
as room (6,0). The room: spawn at (8,112) on the left; three fall floors next
to it at x 48-64, y 112; a fourth at (96,104) under the spring at (96,96); two
on the right wall at (112,56), (112,64); the balloon at (48,32); the exit at
the top left.

## The reference: TAS8, 84 frames, balloon seed 0

`tasdatabase/classic/any/TAS8.tas`: header `[0,]`, 61 inputs. The header is
the balloon's offset: the TAS tool (gonengazit/UniversalClassicTas) sets each
balloon's `offset` instead of `rnd(1)` (its README, "RNG manipulation"). So
TAS files fix the draw, and `pico8_diff/replay.py --balloon-seeds 0` now does
the same. In the original cart at prologue offset 23 (input 0 on frame 24,

under PICO-8's own `rnd` only some replays do. Fitted to celeste-minimal by
`rewrite trajectory` and verified on a real PICO-8 with seed 0:
`tas/room_7_0_reference_frame_84.txt`.

Our search keeps `rnd` an interval at every level (decided with Philippe for
room (5,0), 2026-09-20): a confirmed horizon is "some phase trajectory

with ONE seed before it counts.

## Built: the floors' TIMERS level (`t`, `FloorsPrecision::Timers`)

Between `b` and exact: every floor's `state` and `collideable` stay exact;
only the countdowns - each floor's `delay` and the balloon's `timer` - are
stored as the whole 16.16 range (`widen::widen_floor_timers`,
`runtime2::FLOOR_TIMER_RANGE`, the same projection in `Rt2::widen_to`). An
idle floor never reads its `delay` (a break sets it), so an untouched floor is
exact; a broken one keeps its phase (shaking / hidden) and forgets only how
far in: its `delay <= 0` is then an interval comparison, which the split
(`Domain::split_compare`) forks into two exact-`state` outcomes. The cart only
compares the countdowns with 0 and decrements them, so the whole range is as
precise as any tighter one, and it is closed under the decrement (a first try
with [-1024, 60] failed its own containment premise: the split does not narrow
the stored interval, so `-1` left the range). Ladder: `r0sxht, r0sxh, r1sxh ..
r15sxh, rxsx`; the reference engine refuses a timers level (witness at exact).

Kernels: 472,592 bodies, 2.37M fused nodes (exact: 13,526 / 1.0M); every
floor's split is enumerated in every kernel (largest 8,193 bodies = 2^13), the
build 190 s and 51 GB peak.

## `mget` outside the map (fixed)

At step 118 the timers forward aborted in a kernel: `mget out of range`.
`spikes_at` loops `for i=max(0,flr(x/8)),min(15,..)`; the branch-free kernel
unrolls it and evaluates the second column for every lane, which for a player
at x >= 119 is room column 16, map x = 128. PICO-8's `mget` returns 0 outside
the map; `CartData::mget` and `zn_mget` now do the same (a fractional
coordinate still refuses).

## Built and measured: the floors widened but where the player overlaps (`n`)

Branch `floor-overlap-widening`. `b`'s level 0 had players stuck INSIDE a
spawn floor (`rewrite ancestry`): they entered while it was "maybe absent", and
every later move was refused while it read "maybe present". The design
(Philippe): widen a floor as `b` does, except where the player overlaps it at
the end of the frame (the cart's `floor.collide(player, 0, 0)`).

`FloorsPrecision::Near`, spec letter `n` (`r0sxhn`), between `b` and `t`:

- `state` stored as the interval `[0, 2]` (`runtime2::FLOOR_STATE_RANGE`),
  `collideable` unknown, per lane: `Sel(overlap, computed, widened)`
  (`widen::widen_near_floors`). The overlap is `runtime2::floor_player_window`
  (the hitboxes checked on the traced state; an interval position counts only
  if it certainly overlaps). The spring's floor stays exact (by ordinal,
  `widen::spring_floor_ordinals`: the walk's representatives hold blanked
  positions).
- `delay` (and the balloon's `timer`): `t`'s whole range, overlap or not. NOT
  exact under overlap, a deviation from the brief: a floor the player enters was
  widened the frame before, so its exact `delay` is not in the row, and the mark
  filter keys a row by its projection (`Rt2::widen_to`), which has no history -
  the projection of the concrete state would be a row the level never makes.
  Nothing is lost: an overlapped floor is hidden and comes back only `if delay
  <= 0 and not check(player,0,0)`.
- Input: `state` an interval input; its update's `state == k` is split by
  `verify::split_undecided_selects`, which now knows `==` (`Symbolic::
  may_answers`: may be equal iff the ranges meet, may differ iff they are not
  the same single number) and NARROWS the equal side (`x` read as `k`): an
  outcome that keeps a floor exact must store the state the projection would.
  `collideable` a `ubool` input (a new `CellRepr::UBool`: val and known masks),
  forked by `Symbolic::fork_maybe_unknown` (an `Ints` fork over the lane's
  choice set: a known lane takes its own value, an unknown one both).
- Output: `TCol::Bool` stores 2 for an unknown lane, only for a root that reads
  the output unknown (`AsmField::may_unknown`); a `state` is an interval column
  in every outcome (`out_fields`), and a point in an interval field is keyed
  and stored as `[v, v]` (`konst_av`, `KeyField` span).
- The reference engine refuses it (as `b` and `t`).

Checks: `CELESTE_KERNEL_KEY_CHECK=1` through step 85 (no disagreement);
`rewrite diag-project` (new): every row of the `t` tree at steps 1-96 (7.88M),

solid: that is the price of widening `collideable` at all.

## RESULT (2026-10-01): room (7,0) exit at FRAME 84 - ties TAS8

The level-0 blowups above were a TRACER BUG, not the abstraction: the
boolean join of an undecided floor's `collideable` with the player's overlap
test threw the overlap away (`7f6b96e`), so every collision near a floor read
"maybe" - on the ground, wall jumps off nothing (found with `rewrite spurious`
and `rerun-row`; `rewrite ref-check` against the reference engine catches it).
Then, in order: the spring's phase widened with the floors, a floor's input
`collideable` a fork (consistent across reads), an escaping atom-joined value
a fork restricted per lane (`a1d3d5b`); the overlap level `n` on that base
with `collideable` derived from `state` and the spring as intervals
(`9493327`).

`n` level 0 (split frame): step 110 2.89M states (timers 3.35M, b 6.77M),
step 130 4.09M (timers 26.7M), to step 168 at most 15.4M a step, 433M
visited, 22.7 GB peak, steps 110-168 in ~8 min. Kernels 26,753 bodies /
0.80M fused nodes, largest 2,745 bodies.

Ladder `r0sxhn, r0sxh, r1sxh .. r15sxh, rxsx` at h168: first wins (steps) 134,
134, 142, 152, 156, 160, 162, 164, 164, 164, 168 x7; marks 10.8M at level 0
down to 4,308 exact. OPTIMAL 168 = frame 84. Witness (339 steps, 0 dead
ends) replays on a real PICO-8 with balloon seed 0 or 0.25:
`tas/room_7_0_exit_frame_84.txt`. Ties TAS8.
