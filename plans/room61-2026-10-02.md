## What it took, in order

1. **The near level could not trace the spawn regions** (>4096 outcomes):
   a floor the player might overlap stored its computed `state` on every
   outcome, so the split pass resolved each such floor's whole update and
   multiplied them. Fixed `09505c7`: an overlapped floor stores the cart's
   invariant (hidden), owed per lane. 287k bodies.
2. **The level -1 table** failed on the spawn prefix (the balloon's phase
   read from the walk's placeholder): fixed `a932619` (with (7,1), (0,2)).
3. **A soundness bug** `52a368a` (found in room (0,2)): `tile_flag_over` read
   only tile row 0 for a wholly unknown `y`; this room's spawn-frame kernels
   put the new player in the air. Every (6,1) run before it was discarded.
4. **Per-lane cost**: unsplit `n` level 0 ran ~1 ms per input lane (each
   abstract floor's update and every button configuration multiplied in one
   kernel): f54 at 13 min a frame. `443a281` absorbed case-split outcomes
   (bodies 288k -> 140k, frames 7-21% faster); not enough.
   Alternatives measured with the filter (f40-f55): exact floors explode
   (65.8M states at f48, x1.6 a frame); timers-only (`t`) OOMed building its
   kernels at 60 GB; floors fully unknown (`b`) 480k bodies, 81 s at f40.
5. **The split frame** (Philippe: fully abstract + split kernels, as for the
   clouds room): its dedup bug fixed `e4e0f1a` (a global set to nil kept its
   slot; floors widened between the halves where the player reads them).
   Split level 0: identical states to unsplit at every frame (f40 329,934,
   f45 1,255,157), f2-f45 in 152 s against 955 s, 23k bodies, 7 GB.
6. Two `Rt2::widen_to` assumptions (a uniform column for the balloon's start
   and a floor's position; per-lane at split level 1): `4503c4c`, `17b659a`.
